# 図の規約

PR・ADR など、レビューや判断のために読む文書に図を添えるときの決まり。図は archify スキル（`~/.claude/skills/archify/SKILL.md`）で作る。図は本文の説明を補うもので、本文を図だけに置き換えない。

## 図を入れる場面

次のどれかに当たるなら、図を 1 つ以上入れる。文章だけだと読み手が頭の中で組み立て直す必要があるためである。typo の修正や文言の変更など、どれにも当たらないものには入れない。

- 処理の流れ、呼び出し順、状態、データ構造、責務の境界のどれかが変わる
- 変更が複数の PR やリポジトリにまたがり、マージ順や依存がある
- 設定や手順の変更で、人やツールが行う作業の流れが変わる

図を入れるときは次に従う。

- 図の直前に、その図で何を見てほしいかを 1 文で書く
- 1 つの図のノードは 15 個程度までにする。超えるなら観点ごとに図を分ける
- 変更の前後を比べる図は、下の「AsIs-ToBe 比較」に従う

## 図の種類

フローチャートに寄せず、示したいものに合わせて archify の type を選ぶ。

| 示したいもの                               | type           |
| ------------------------------------------ | -------------- |
| 処理の分岐・手順                           | `workflow`     |
| サービス・モジュール間の呼び出し順、非同期 | `sequence`     |
| データの流れと変換                         | `dataflow`     |
| ステータスと遷移の条件                     | `lifecycle`    |
| テーブルとリレーション                     | `erd`          |
| 型・クラスの継承や依存                     | `class`        |
| システム構成、レイヤーと責務の境界         | `architecture` |
| 段階的な移行・リリースの日程               | `timeline`     |

## 置き場所ごとの載せ方

archify の出力は単体の HTML である。置き場所によって載せるものを変える。

| 置き場所           | 載せるもの                                                     |
| ------------------ | -------------------------------------------------------------- |
| GitHub の PR       | HTML のビューアの Export メニューで書き出した PNG を本文に貼る |
| Notion（ADR など） | HTML を `/HTML` の HTML ブロックにアップロードして埋め込む     |

- PR の本文では、図を置く位置に PNG の相対パスで `![図の説明](./<PNG のパス>)` と書く。`gh pr create` か `gh pr edit` に `--body-file <本文> --attach <PNG のパス>` を付けると、PNG がアップロードされ、参照がアップロード先の URL に書き換わる（gh 2.105.0 で確認。相対パスは本文ファイルのディレクトリ基準）
- Notion の HTML ブロックは埋め込んだ後に中身を編集できない。図を直したら HTML を作り直してアップロードし直す
- 作った HTML はリポジトリにコミットしない。生成元の JSON も同じ

## AsIs-ToBe 比較

- `architecture` の変更前後は、AsIs と ToBe の JSON を 1 つずつ作り、`node ~/.claude/skills/archify/bin/archify.mjs compare architecture <AsIs.json> <ToBe.json> <出力.html>` で 1 枚の比較図にする
- ほかの type は 1 枚で比較できない。ToBe の図を 1 枚作り、変わった箇所を図の直前の 1 文で書く。前後を並べて見せる必要があるときだけ、AsIs と ToBe を別の図にして AsIs を先に置く
