# コミットメッセージ規約

Conventional Commits を基本に、次の独自仕様を足す。

## フォーマット

```
<type>(<scope>): <subject> [<ticket-id>]

<body>
```

- 日本語で書く（技術用語は英語可）
- type は `feat` / `fix` / `refactor` / `perf` / `docs` / `style` / `test` / `chore` の 8 種
- ヘッダー全体で 72 文字以内（subject は 50 文字以内が目安）
- 2 行目は必ず空行にし、ヘッダーと本文を空行で区切る
- 箇条書きは 1 項目を 1 行で書き、途中で改行しない（72 文字の制限はヘッダーだけにかかる）
- チケット ID が判明しているときだけ、subject 末尾に `[TICKET-ID]` を付ける
- GitHub PR / Issue は同一リポジトリ内でも `{org}/{repo}#{番号}` で参照する（ベアの `#123` は転記先でリンクが切れる）

## 提案手順

- 1 案だけ出す。`type(scope): subject` と変更点の箇条書きだけを書く。変更理由の段落と footer（`Closes` など）は書かない
- 1 リポジトリにつき 1 コミット分を提案する。変更が複数のリポジトリにまたがるときは、リポジトリ名を見出しにして分ける

## 出力フォーマット

コードブロックにはコミットメッセージだけを入れる（全体をコードブロックで囲まない）。type / scope の選択理由を短く添える。

```
type(scope): subject

- 変更点1
```
