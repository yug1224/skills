# 指摘対応ルール

PR コメント・レビュー Bot の指摘・セルフレビューを判定し、妥当なものだけコードで直す手順。重要度・比較先・指摘の絞り方は `code-review-rule.md`、反証は `review-report-rule.md` の「反証」に従う。

## 前提

- 新しい層・抽象を足さない。実装の規約は `~/.claude/skills/local-rules/references/conventions/coding-rule.local.md`（存在時）に従う
- `code-review-rule.md` の「ローカル検証」に従う（typecheck は手順があれば実行し、無ければ CI に任せる）。CI 失敗は `gh run view --log-failed` で読み、コード側で潰せるものだけ直す
- P0 / P1 を直すときは、先に失敗するテストを書いて失敗を確かめ、修正後に通ることを確かめる。テストで再現できないものは、再現手順と結果を報告に書く
- レビュー Bot の指摘は仮説として扱い、反証で崩れず再現できたものだけ直す（対象 Bot と扱いは `~/.claude/skills/local-rules/references/conventions/review-feedback-rule.local.md` の「Bot の指摘の扱い」）。誤検知や既存パターン破壊になる修正はしない

## 判定

各指摘を一つに分類する。

| 区分        | 内容                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| **対応**    | このセッションでコードを直す                                                                           |
| **WONTFIX** | 誤検知 / 既存ドメインと衝突（P2 に限る）。理由を 1 行                                                  |
| **待ち**    | git 書き込み / GitHub 書き込み / CI に任せた typecheck / レビュー Bot 再実行 / PR / ドキュメントツール |

外部からの指摘も、対応にする前に「反証」を通す。崩れたものは WONTFIX（誤検知）にする。

## ループ（最大 3 ラウンド）

1. 入力を集める（書き込みはしない）。PR はチャットに無いコメント・CI 結果だけ読み取りの `gh` で取る。diff 貼り付けはそれを使う。ローカル差分は `code-review-rule` の「対象と比較先」に従う。どれも無ければ待ち「対象の PR または diff を渡してください」で終了
2. セルフレビューで P0 / P1 / P2 を出し、反証を通してから分類し、対応だけ実装する
3. 「ローカル検証」を実行し、落ちたものと自分の修正による回帰だけを直す。2 ラウンド目以降は新しい指摘を足さない
4. コード側の P0 / P1 / P2 が無くなるか残りが WONTFIX と待ちだけになったら終了。前のラウンドより P0 / P1 / P2 の件数が減らなければ、上限の前でも止める。止めたときと 3 ラウンドで残った P0 / P1 / P2 は「未解決」として報告する

## 終了報告

- **直したこと**
- **検証結果**（実行したコマンドと結果。P0 / P1 は修正前に失敗し修正後に通ったテスト）
- **WONTFIX**（指摘 → 理由）
- **未解決**（潰せなかった P0 / P1 / P2。無ければ「なし」）
- **未検証**（typecheck など実行しなかったもの）
- **待ち**（git / CI / レビュー Bot / PR / ドキュメントツール）
- **反証できなかった点**（無ければ「なし」）
