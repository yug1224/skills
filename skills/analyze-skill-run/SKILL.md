実際のセッションで Skill がどう動いたかを手順ごとに確かめ、Skill の本文や規約の直す箇所を提案する。調べるだけで、ファイルは変えない。

**Input**: セッション（ID、`@` で渡したセッション、記録の `.jsonl` のパスのいずれか）と、見たい Skill 名（任意。無ければ記録の中で呼ばれた Skill をすべて見る）。セッションが無ければ入力を求めて終了する。

## Steps

1. セッションの記録を読む。ID なら `mcp__ccd_session_mgmt__list_events` でさかのぼり、要約で途切れていれば、記録の `.jsonl`（`~/.claude/projects/*/<session-id>.jsonl`）からユーザーとアシスタントの発言とツール呼び出しを抜き出す
2. 対象の Skill の本文と、その Skill が Read する規約を、`~/.claude/skills/` から読む。記録の中で読まれた本文が今の本文と違えば、その後に直っていないかを今の本文で確かめる
3. Skill の手順ごとに、実際にしたことを並べ、次の 5 つに当たる箇所を探す
   - **飛ばした手順**: 手順にあるのに、していない・別のやり方で代えた
   - **問い直し**: ユーザーに答えをもらってから事実を調べ、同じことを問い直した
   - **手戻り**: 後の Skill やレビューで見つかり、前の Skill に戻って直した（どの手順で防げたかを書く）
   - **出し直し**: 同じ残件や注意を、何度も報告し直した
   - **詰まり**: 呼べない Skill・権限・タイムアウトなどで止まり、ユーザーの入力を待った
4. 当たった箇所ごとに原因を 1 つに絞り、直す箇所（Skill の本文・規約・テンプレート）と書き換え案を出す。同じ原因の箇所はまとめる。手順の外で済んだことや、1 回だけの事故は直す箇所にしない
5. 「出力テンプレート」で提示する

## 出力テンプレート

```markdown
## 対象

- **セッション**: {タイトルか ID}
- **Skill**: {見た Skill}

## 手順ごとの実際

| Skill | 手順 | 実際 | 判定 |
| ----- | ---- | ---- | ---- |

## 直す箇所

### 1. {直す箇所の要約}

- **起きたこと**: {記録のどこで、何が起きたか}
- **原因**: {Skill のどの記述が足りない・食い違うか}
- **直す箇所**: `path`
- **書き換え案**: {足す・変える文}

## 直さないこと

- {見つけたが直さないことと理由}
```
