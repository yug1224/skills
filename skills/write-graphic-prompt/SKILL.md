name: write-graphic-prompt
description: PR・ADR・開発ログ・自由記述から、Gemini（Nano Banana Pro）でグラフィックレコード風画像を作るための構造プロンプトを 1 本出力する。グラレコ画像・図解画像のプロンプトがほしいときに使う。画像は生成しない
---

入力を「背景・課題」「結論」「今後」の 3 まとまりに圧縮し、Gemini へ貼る構造プロンプト（日本語の描画内容つき）を fenced ブロック 1 つで出す。画風・トンマナは含めない（ユーザーが Gemini へ先に別メッセージで送る）。

**Input**: PR URL / `.md` パス / 自由記述（複数可）。空なら求めて停止する。

**オプション**:

| 引数                | 用途                                                                  |
| ------------------- | --------------------------------------------------------------------- |
| `layout:<name>`     | レイアウトを指定する。`auto` は内容に合うものを選ぶ。未指定はランダム |
| `size:WIDTHxHEIGHT` | 解像度を上書きする（例: `size:2560x1440`）。未指定は `1920x1080`      |

## Steps

1. 材料を取得する（PR は `gh pr view` / `gh pr diff`、パスは Read、URL は取得）。取得できなければ要点の貼り付けを求めて停止する
2. 「まとまりの割り当て」に従って項目を抽出する。情報が足りないまとまりは推測で埋めず、1〜2 点確認する
3. レイアウトを決める。`layout:` 未指定なら Bash で `echo $((RANDOM % 6))` を実行し、その番号のプリセットを使う（LLM の「ランダム」は偏るため、乱数はシェルから取る）。シェルが使えない環境では `auto` と同じ扱いにする
4. `~/.claude/skills/write-graphic-prompt/references/template.md` を Read し、「描画内容の書き方」に従って `{描画内容}` を書き、「出力テンプレート」の `{レイアウト指示}` `{描画内容}` `{解像度}` を差し替える
5. 「出力前の点検」を通してから、導線文 1 行と fenced `text` ブロック 1 つだけを出す

## まとまりの割り当て

| まとまり   | 中身                                       | 項目数       | 面積     |
| ---------- | ------------------------------------------ | ------------ | -------- |
| 背景・課題 | 現状・経緯と、そこで何が困っていたか・制約 | 2〜4         | 小       |
| 結論       | 採用した設計・変更内容・判断理由・検証結果 | 3〜6         | **最大** |
| 今後       | 未完了・後続 PR・フォロー                  | 0〜2（任意） | 小       |

背景と課題は分けず、「現状 → だから何が困るか」の順に 1 まとまりで書く。

ソース別の読み方:

- **PR**: 背景・課題=文脈と PR が解く問題、結論=変更内容・トレードオフ・テスト、今後=follow-up・TODO
- **ADR**: 背景・課題=コンテキストと満たすべき要件・制約、結論=決定内容と影響、今後=未決事項・移行の残り
- **開発ログ**: 概要・分析→背景・課題、方針・実装・検証→結論、残課題→今後
- **自由記述**: 書かれた内容を 3 まとまりへ振り分ける

今後が空なら、そのまとまりはレイアウト指示・描画内容の両方から消す。

## レイアウトプリセット

どれも「結論が最大」を満たす。番号は Step 3 の乱数に対応する。

| #   | name           | レイアウト指示（テンプレートへそのまま入れる）                                                                        |
| --- | -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 0   | `answer-first` | 結論を画面の左約 2/3 に大きく置く。右側の上に背景・課題、右側の下に今後を小さく置く                                   |
| 1   | `hero`         | 結論を中央の大きなパネルにする。背景・課題は左側に細く、今後は右側に細く置く                                          |
| 2   | `top-bottom`   | 上段に背景・課題を全幅の細い帯で置き、下段の残り全部を結論にする。今後は結論パネルの右端に寄せる                      |
| 3   | `radial`       | 結論を中央の大きな島として描き、背景・課題と今後をその周りに小さな島として配置し、矢印で結論へつなぐ                  |
| 4   | `before-after` | 左に背景・課題を「Before」として小さく置き、大きな矢印を挟んで右に結論を「After」として大きく描く。今後は右下に小さく |
| 5   | `road`         | 左上から右下へ曲がる道に沿って背景・課題を置き、道の到達点にある広場を結論として大きく描く。今後は道の先に小さく      |

`auto` では、変更前後の対比が主題なら `before-after`、手順や時系列が主題なら `road`、1 つの設計判断が主題なら `hero` を選ぶ。

## 出力前の点検

- [ ] 結論が最も項目数・情報量が多く、レイアウト指示でも最大になっている
- [ ] 背景・課題が 2〜4 項目、今後が 0〜2 項目。今後が空なら見出しもレイアウト指示の該当文も消えている
- [ ] 描画内容が 1500〜2500 字の日本語で、画像に描く文言が「」で囲まれている
- [ ] 描画内容を次のコマンドの標準入力に渡し、`ok` が出る（出た漢字は JIS 第一・第二水準外なので置き換える）: `python3 -c 'import sys,re;bad=sorted({c for c in sys.stdin.read() if re.match(r"[\u3400-\u9fff\uf900-\ufaff\U00020000-\U0003ffff]",c) and not c.encode("iso2022_jp",errors="ignore")});print("".join(bad) or "ok")'`
- [ ] fenced ブロック内に画風・色・質感・トーンの指定がない
- [ ] 機密情報・パス全文・diff 行がない

## 出力形式

次の導線文 1 行のあとに、fenced `text` ブロックを 1 つだけ出す。選んだレイアウト名を導線文の末尾に `（layout: <name>）` で添える。ほかの説明・抽出結果・別案は出さない。

「Gemini で先に画風・トンマナを別メッセージで指示し、続けて以下のブロックを貼り付けて画像を生成してください。」
