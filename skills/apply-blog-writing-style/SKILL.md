# ブログ執筆スタイルガイド

yug1224（ぷーじ）の過去記事から抽出した文体・構成・トーンのルール。

## 基底規範との関係

作業前に `~/.claude/skills/apply-japanese-tech-writing/SKILL.md`（JTW）を Read し、体験記・読み物なら `~/.claude/skills/apply-cognitive-rhythm-writing/SKILL.md`（CRW）も Read する。矛盾時は本ファイルを優先する（blog コンテキスト）。

### Override 表（blog が勝つ）

表に無い項目は本ファイル本文と下記「共通適用」に従う。

| 論点                         | 基底                            | blog override                                                                                                                                                                                         |
| ---------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 挨拶・「はじめに／おわりに」 | CRW: 態度のない議題表のみ禁止   | **必須**（導入・まとめパターンに従う）。導入のスコープ宣言は残す                                                                                                                                      |
| 見出し「おわりに／まとめ」   | JTW: 空句の「まとめると」は禁止 | **見出し「おわりに」または「まとめ」は必須**。総括空句は禁止のまま                                                                                                                                    |
| 二人称・読者への語りかけ     | CRW: 冒頭・結びの境界のみ       | カジュアルな語りかけ可（導入・まとめ中心）                                                                                                                                                            |
| 認知リズム（CRW）            | CRW 全体                        | 体験記・読み物のみ **opt-in**（失敗談・感情の起伏・場面描写が中心のとき）。opt-in 時は CRW をフル適用。ただし導入のスコープ宣言は本ファイル優先で残し、態度のない議題表と節頭「本節では」は禁止のまま |

**共通適用**（Override しない）: ダッシュ抑制、LLM 空句禁止、根拠なき断言抑制、冗長な言い換え禁止、論証の誠実さ。

## 基本トーン

- **一人称**: 自分・私（文中で自然に混在してよい）
- **語尾**: 「です・ます」ベース。親しみやすさを出すために体言止めや口語（「〜ですよね」「〜しました！」）を適度に混ぜる
- **口語度**: カジュアル寄り。堅すぎず馴れ馴れしすぎないバランス
- **絵文字**: タイトルに 1 つ（Zenn の emoji フィールド）。本文中ではほぼ使わない

## 導入パターン

1. **挨拶**: 「こんにちは。ぷーじ（[@yug1224](https://x.com/yug1224)）です。」で始める
2. **文脈の提示**: Advent Calendar やイベント登壇など、執筆のきっかけがあれば冒頭で示す
3. **課題提起 or フック**: 読者が共感できる問題提起・疑問・経験の共有を 3-5 行で行う
4. **記事のスコープ宣言**: この記事で何を伝えるか 1-2 文で明示する

## 見出し構成

- **H2 を主軸**に構成する（4-8 個程度）
- **H3 は H2 の補足**として使う。H4 以下はほぼ使わない
- 見出しは短く具体的に。疑問形や体言止めも可
- 「はじめに」「おわりに」（または「まとめ」）を置く

## 本文の書き方

- **1 段落は 3-5 行**を目安に。長い段落は避ける
- **箇条書き・表・コードブロック**を積極的に使い、テキストの壁を作らない
- **太字**で要点を強調する（多用しすぎない。段落に 1-2 箇所まで）
- **引用ブロック**: 過去の自分の発言や外部記事からの引用に使う
- **埋め込みリンク**: 参照先の URL は Zenn/Qiita の埋め込み記法で本文中に配置する（末尾参考リンク集にまとめるのではなく、文脈に沿って登場させる）

## 論述の流儀（防御力）

`~/.claude/skills/shared-rules/references/blog/blog-review-rule.md` の観点 1（防御力）を満たすように書く。主観には「私の経験では」「私たちのチームでは」などのマーカーを付け、出典は「本文の書き方」の埋め込みリンクで添える。

## まとめパターン

- 記事全体の振り返りを簡潔に（3-5 行）
- 今後の展望や読者へのメッセージで締める
- 自社や自分の SNS/プロフィールへのリンクを添えることがある

## 画像・ビジュアル

- 記事冒頭にアイキャッチ画像を 1 枚配置する（AI 生成画像やイベント写真）
- 本文中のスクリーンショット・図表は説明の直後に置く
- 画像にはキャプション（イタリック記法 `_caption_`）を付けることがある

## やらないこと

- 箇条書きだけで構成する（散文とのバランスを取る）
- `blog-review-rule` の観点 6（炎上リスク）のチェック項目に当たる表現
