チケットの課題を読み取り、コードベースを調べて原因を特定し、松竹梅の対応方針を提案する。調査と提案だけで、コードは変更しない。

**Input**: チケット URL または ID（必須）。

## Steps

1. チケットを取得する（`~/.claude/skills/local-rules/references/conventions/ticket-retrieval-rule.local.md` が存在すれば Read してその手順に従う）
2. 原因を調べる前に、再現手順か失敗するテストを作り、実行して失敗を確かめる。テストは一時ファイルに書き、終わったら消す。再現できなければ、試した手順と結果を「再現」に書いて先に進む
3. 原因を調べ、根本原因と直接原因を分けて特定する
4. 対応方針を松竹梅で出し、「出力テンプレート」で提示する。各案には、直ったと判断する完了条件と、それを示す証拠（通るテスト・実行結果）を書く
   - **松**: 根本原因の解消と再発防止
   - **竹**: 直接原因の修正
   - **梅**: 最小変更での解消

## 出力テンプレート

原因を特定できなかったときは、調べた範囲と推測を書いたうえで「追加調査の方向性」を足す。

```markdown
## 課題サマリー

{チケット内容を 1〜2 文}

## 再現

- **手順**: {実行したテストかコマンド}
- **期待値**:
- **実際の結果**:

## 調査結果

- **根本原因**:
- **直接原因**:
- **関連コード**: `path:行` と該当箇所の引用

## 影響範囲

- {影響を受けるモジュール・機能}

## 対応方針（松竹梅）

### 松

- **内容**:
- **変更対象**:
- **完了条件 / 証拠**:
- **リスク**:
- **想定工数**:

### 竹

（松と同じ項目）

### 梅

（松と同じ項目）

## 推奨

{推奨する方針と理由}
```
