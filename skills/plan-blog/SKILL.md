description: テーマと概要からブログ記事の執筆プランを作成する。ブログ記事の執筆プランを立てたいときに使う（記事本文は書かない）
---

ブログ記事のテーマと概要・補足情報を受け取り、執筆プランを Markdown で作成する。プランは反復前提で、既存プランファイルの修正も受け付ける。

**Input**: テーマ・概要・補足（参考リンク、対象読者、主張など）。既存プランファイルのパスで修正版も可。

## Steps

### 1. ルールの読み込み

- `~/.claude/skills/apply-japanese-tech-writing/SKILL.md`
- `~/.claude/skills/apply-blog-writing-style/SKILL.md`
- 体験記・読み物寄りのときだけ `~/.claude/skills/apply-cognitive-rhythm-writing/SKILL.md`

### 2. 入力の解析

既存プランファイルが指定されていれば Read し、修正方向を確認する。テーマが決まっていなければ、候補を 3 つ前後出して選んでもらう。

### 3. 執筆プランの作成

以下の節を含める:

- 仮タイトル
- 基本情報（テーマ、記事タイプ、対象読者、前提知識、想定ボリューム: 軽め 1000 字 / 標準 2000〜3000 字 / 重め）
- 中心となる主張・差別化ポイント
- 見出し構成
- 候補タイトル（3 案以上。30〜50 字で、ツール名・技術名・数字を含める）
- メタ情報案（Zenn の emoji 1 つ、type は `tech` か `idea`、topics / tags 3〜5 個、要約 80〜120 字。組織の publication があれば `publication_name`）
- 参考リンク・検証すべき事項
- 公開前チェックの観点メモ

見出し構成は記事タイプに合わせて組み、タイプごとに次の節を落とさない。

| 記事タイプ       | 入れる節                                        |
| ---------------- | ----------------------------------------------- |
| 技術解説・導入記 | 背景・モチベーション、Before / After            |
| チュートリアル   | TL;DR、動作環境（バージョン）、つまずきやすい点 |
| 比較・選定       | 選定基準、候補一覧の表、自分たちが選んだ理由    |
| トラブルシュート | 環境、仮説ごとの調査過程、原因、再発防止        |
| 体験記・キャリア | 背景、得たものと失ったもの、数字やエピソード    |

公開前チェックの観点メモには、少なくとも次を含める。

- frontmatter: `published` / 予約投稿なら `published_at`
- 本文: 同じ語尾の 3 連続、200 字を大きく超える段落、1 段落 3 箇所以上の太字
- 機密: 社内情報・他者の個人情報・スクリーンショットへの写り込み

## Guardrails

衝突時は `apply-blog-writing-style`（blog Override）を優先する。
