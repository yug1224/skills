テック記事の URL・本文・ローカル Markdown から、X 投稿用の**二文要約**を 1 案だけ提案する。

**Input**: 記事 URL / 記事本文の直貼り / ローカル `.md` パスのいずれか（必須。無ければ求めて停止する）。

**オプション**: `with-url` — URL 入力時だけ、fenced ブロック直後に `source: <url>` を 1 行足す（既定オフ）。

## Steps

1. `~/.claude/skills/local-rules/references/overlays/suggest-x-post.md` が存在すれば Read する（矛盾時はこちらを優先）
2. 材料を取得する。取得できなければ要点の貼り付けを求めて停止する
3. 下の「要約文の要件」「文の構成」に従って二文を書く
4. fenced `text` ブロック 1 つ（1 行 1 文の二文）だけを出す。前置き・解説・ハッシュタグ・複数案は出さない

## 要約文の要件

| 項目   | 内容                                                                                   |
| ------ | -------------------------------------------------------------------------------------- |
| 内容   | その技術がどのようなもので、どんな場面で役立つ可能性があるかを具体的に記述する         |
| 文字数 | 全体で 100 文字以内（下記「文字数の数え方」）                                          |
| 文体   | 硬すぎず砕けすぎない自然な口語。断定を避け柔らかい表現を使う。「ですます」調は使わない |

文字数の数え方:

- 単位は Unicode 符号点（`[...]` の文字数と同義）
- 1 文目と 2 文目の間の改行と、markdown fence 記号は数えない

## 文の構成

- 1 文目は事実・特徴、2 文目は自分の反応・評価。間に改行を 1 つ入れる
- 句読点（`。` `、`）は使わない
- 切り口は次のいずれか（または組み合わせ）を参考にする

| 型     | パターン例                    |
| ------ | ----------------------------- |
| 説明型 | 「X は〜する〇〇」            |
| 比較型 | 「既存の〇〇より △△」         |
| 用途型 | 「〇〇したいときに便利な △△」 |
| 特化型 | 「△△に特化した〇〇」          |

## 出力例

facebook/react:

```text
状態変化で必要な部分だけ効率的に更新する宣言的UIライブラリらしい
コンポーネント設計が好きな人に刺さりそうかも
```

astral-sh/ruff:

```text
既存ツールより100倍速いPython用リンター兼フォーマッターらしい
Rust製でちょっと気になる
```
